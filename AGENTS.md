# Authoring discipline

Read [OPERATIONAL.md](OPERATIONAL.md) first. Its forward recoverability, book-heading specificity and inverse generative-curiosity criteria govern educational quality. Put implementation particulars below readable product-relevant headings; keep genuine search aliases. Review the question landscape as a coherent prospective table of contents, not an inventory of isolated facts.

Read [Software/README.md](Software/README.md) before changing software case studies. Reuse the established [Kami authoring contract](https://github.com/JadanPoll/Kami_Uploads_RSM_Tree/blob/main/AGENTS.md), [glossary schema](https://github.com/JadanPoll/Kami_Uploads_RSM_Tree/blob/main/GLOSSARY_SCHEMA.md), and [question types](https://github.com/JadanPoll/Kami_Uploads_RSM_Tree/blob/main/QUESTION_TYPES.md), adapting book-specific references to real-world engineering evidence.

- Each product owns its canonical investigation, independent glossary and replay/evidence records. The parent index and viewer manifest are projections only.
- Start with existing questions, terms, plans and source anchors. Do not rebuild or duplicate them. Preserve stable IDs; vocabulary can grow without mapped questions. Use fresh IDs for distinct concepts, aliases for true synonyms, and redirects for merges.
- AI Pill statistics and set operations surface candidates; do not equate lexical frequency or co-occurrence with conceptual importance, semantic relationships or certification. Retain consequential observations and their scope, then curate vocabulary.
- Distinguish ordinary-language entries, meaningful conditional branches, technical records and larger question-set projections. Tag reviewed questions by dominant obligation and task specificity. Do not manufacture questions for coverage.
- Public education is not exhaustive goal-directed reverse engineering. Preserve compact replay plans, source identity, observations, interpretation and limits. Do not publish private reports, personal state or proprietary bundles.
- HTMlets illustrate mechanisms; use the existing canonical viewer and shared styling. Add machinery only when repeated educational need justifies it.
- Verify real question-to-source and source-to-question traversability. A JSON/schema check is not a successful learner interaction.
