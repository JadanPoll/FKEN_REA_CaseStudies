[AI Pill](https://github.com/JadanPoll/AI_Pill_OS/blob/main/AI_Pill.user.js) is the acquisition and investigation instrument for web applications. This repository is the durable educational result, not a mirror of the instruments or their raw archives.

## Canonical records

Each product owns an independent, evolving investigation folder. Do not combine multiple products into a single growing evidence archive.

| Product | Question landscape | Evidence and replay |
| --- | --- | --- |
| Claude | [investigation.json](Claude/investigation.json) | [evidence.json](Claude/evidence.json) |
| Discord | [investigation.json](Discord/investigation.json) | [evidence.json](Discord/evidence.json) |

Within each folder, `investigation.json` owns questions, mechanism explanations, transferable insights, qualifications and optional HTMlets. `evidence.json` owns replayable JSON plans, run IDs, compact result receipts, source filenames, SHA-256 digests and half-open UTF-16 ranges. Keep stable study IDs and append new evidence rather than overwrite older observations. Reconstructed plans are explicitly marked; fresh deployments may differ.

The software-level [investigation.json](investigation.json) is only a product navigation index, with optional cross-product mechanism references. The root [rsm-view.json](../rsm-view.json) registers the index and product views in the canonical viewer. Neither duplicates educational content. Add a new product folder and its view/index entry when a new product is investigated.

Start from a question, inspect the mechanism, then expand **Investigation plans & receipts** to recover and copy the relevant JSON. Use the retained archive if available; verify digests before treating old offsets as evidence. A successful plan is not necessarily a successful hypothesis test.

## Public persistence discipline

This is a curiosity-led educational collection, not an exhaustive engineering project archive. Preserve the question, investigation plan, observation, interpretation, source identity and limits at the resolution needed to understand or reuse the mechanism. Pursue deeper collection only when a consequential question requires it. Do not republish private reports, user data, session identifiers, credentials or proprietary source bundles. Run IDs here identify local AI Pill investigation receipts, not service sessions. If original evidence cannot be recovered, say so rather than promote the summary into independent certification.

Source-inspected is distinct from runtime-observed, and both are distinct from a demonstrated transferable implementation. New questions can be added without demanding immediate answers. Extend a canonical record as evidence changes; preserve old receipts and stable IDs. Prefer distinct mechanisms over many superficially different examples.

## HTMlets

Optional node field: `htmlet: {title, height, html}`. HTML is a small educational fragment, with local interaction script if useful. The viewer supplies shared typography, controls, metrics and tile styling; the fragment is rendered on demand inside a sandboxed iframe without same-origin access, with restrictive CSP. No external dependency or live application interaction is needed. These examples are conceptual models, not performance measurements or exact reproductions. Keep them small and do not create a new shared primitive unless repeated educational use justifies it.

Initial population: Claude and Discord, 12 mechanism studies, three interactive examples. Source anchors are inspected static evidence, not runtime certification. Viewer and example script syntax checked; live Safari interaction remains unverified.
